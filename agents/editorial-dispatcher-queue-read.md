# Dispatcher / Postmill queue inventory v1 — proposed read-only contract

Status: design candidate for Issues AREN-876/max-editorial-engine#37/#67 and Postmill #52. No endpoint, ACL, migration or runtime activation in this document. Owner: Postmill/Image for native inventory; Dispatcher for admission and policy; Editorial Engine for upstream identity/coverage. Operator approved allocation 031 Profiles/Text, 032 Dispatcher Policy, 033 Dispatcher Finance. No additional number allocated.

## Scope and source of truth

A server-owned registry resolves each requested Editorial channel to exactly one (organizationId, integrationId, Integration.internalId, providerIdentifier, Editorial channel ID, profile ref/pin). Bind the authenticated machine principal to permitted scopes; do not accept a caller assertion as authority. Unsupported/unmapped/disabled/deleted integrations and ambiguous mapping must be reported as incomplete, not empty. v1 does not silently assume current test MAX target covers all channels. Mock/test material, unsupported factual downstream and ordinary non-managed posts are not Editorial supply; ordinary native scheduled posts are nevertheless reported separately as slot occupancy. No content, feedback, image, storage paths, tokens or credentials.

Native sources at Postmill #52: Post, Integration, EditorialDraftReceipt (request.scope and targetSnapshot), EditorialReviewAnchor, EditorialDecisionOutbox/Result/DeliveryReservation/Recovery, EditorialTextInstall/TextRevision, EditorialImageImport/Receipt, EditorialRelease. Reuse verified review reducer semantics, not listPending* LIMIT-based sweeps or latest row by timestamp. Native release source is a DRAFT and publication copy has a different group; join EditorialRelease.sourcePostId -> publicationPostId, not group equality. Post has unique (organizationId, editorialTaskId); EditorialRelease has unique source and publication IDs. Validate both endpoints' org/integration/target and receipt/release confirmed sequence; check native delivery state. No reliance on ordinary campaign approvalStatus as Editorial approval.

## Logical unit and completeness

Count once per (organizationId, editorial channel ID, task ID) with reconciled immutable receipt/profile/group/sourcePostId. A source draft, its text revisions, image revisions, pending decisions, and linked native publication copy are one unit. Never count outbox rows or release copies as new supply. Detect duplicate claims, orphan links/receipts, mismatched channel/profile/task/target, deleted rows and invalid state instead of filtering them away. If identity is unresolved report diagnostic counts separately; do not invent a unit key or credit supply. Compare exact unit identity set against the Editorial Engine snapshot including upstream tasks not yet imported; distinguish upstream-only, native-only and disagreement. Upstream-only tasks are not Postmill drafts. No full-channel claim until both sides' coverage is established; do not sum their counts.

For each reconciled native unit assign exactly one bucket in this precedence:
1. blocked_unknown: contradictory/missing evidence, unresolved delivery/import/revision outcome, invalid binding or deletion; native ERROR or unverified delivery. A valid PUBLISHING operation with no uncertainty evidence is not automatically an error.
2. published: verified linked publication is PUBLISHED; terminal release evidence agrees.
3. rejected: confirmed terminal rejection with no contradictory release.
4. publishing: verified linked publication is PUBLISHING.
5. scheduled: verified linked publication is QUEUE; use actual publishDate and confirmed release, classify overdue separately.
6. approved_unscheduled: confirmed current final approval (or explicitly qualified text-only mode), no release, no unresolved event or revision; not publication authority.
7. review: remaining verified DRAFT, including pending text/image decisions, text revisions and image generation; annotate phase, pending operation counts and approval state without counting them as units.
Any other state -> blocked_unknown. All mutually exclusive buckets sum to reconciled units; terminal published/rejected excluded from active backlog. Active backlog = review + approved_unscheduled + scheduled + publishing + blocked_unknown, with separately reported unresolved identities; eligible reserve/supply must not include blocked/unknown or unsupported profiles. Historical terminal counts have an explicit retention/coverage window; if terminal evidence is pruned, declare history incomplete. No arbitrary truncation of active queue.

## Response candidate

Versioned read-only response with snapshot_id (opaque), contract_version, observed_at UTC (database transaction snapshot), response_generated_at UTC, scope mapping revision, coverage status complete|partial|unknown, reason codes, per-channel counts (above), approval/phase counts as nonadditive breakdowns, identity reconciliation evidence/digest and counts, native slot occupancy (ordinary + managed, disjoint), next scheduled publishDate, overdue scheduled count and bounded time histogram with explicit timezone/horizon. If identity inventory is paginated, all pages must share one immutable snapshot and completeness marker; aggregates cannot be derived from partial pages. Snapshot does not grant mutation authority. Use a single read-only REPEATABLE READ transaction for all native reads, no locks that serialize writers, no side effects, no use of cached partial totals. Cross-database reads are not atomic: return separate source observation timestamps and identity digests, detect changes/inconsistency and hold when not reconciled. Avoid raw snapshot credentials or transaction internals.

Dispatcher owns max age and permitted inter-source skew as explicit policy values; until agreed/qualified, hold auto-refill. Evaluate freshness at consumption, not just response creation. A missing scope, stale result, timeout, unknown bucket, identity mismatch, unsupported coverage, unavailable source or incompatible version must never turn into zero backlog or implicit permission; hold affected channel and report reason. Explicit complete zero requires both sides' reconciled evidence. No schedule, release, approval, generation, dispatch, budget or write permission in response. No new paid requests under 022 before durable one-use send-grant qualification; this read contract does not affect that fence.

## Qualification before implementation/activation

Separate reviewed read-only principal/transport, scoped grants and signed response/request if reusing the machine bridge; deny unauthorized scopes, replays and tampered scope. Actual PostgreSQL tests: source+release count once, 3-part content/revisions/outbox do not multiply, release concurrent snapshot old-or-new but never double/zero, pending/unknown/rejected/published, scheduled/overdue/ordinary occupied slots, duplicate/orphan/deleted/wrong-org/wrong-channel/profile, missing scopes vs verified zero, stale/skew/reconciliation failure, no writes or release privileges, exact combined 023–030 upgrade/restore. Real multi-channel scope and full inventory coverage must be demonstrated. Existing narrow test-target read methods are not the complete queue contract. No implementation/activation until agreement on eligibility, freshness/skew, coverage/retention and identity reconciliation.
